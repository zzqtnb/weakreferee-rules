# 模型档案

这个目录记的是「**某个模型在参数形态上容易犯什么错**」，一个模型一个 JSON。

## 现在为什么只有一个

`deepseek-chat.json` 是唯一有实测数据的档案：18,735 次去重调用、403 次命中，
来自作者环境（2026-11，Windows 上的 DSH 桌面版）。

别的模型曾经各有一个占位档案，后来都删了——它们只有名字和厂商，一次调用都没跑过。
**占位不等于收录**：一个空档案读起来像「这个模型也被考察过」，实际上什么都不知道。
想加，按下面的格式跑出数据再提交。

## 怎么加一个

复制 `_template.json` 改名成你的模型 id（和 API 里 `model` 参数一模一样），然后填：

| 字段 | 填什么 |
|---|---|
| `model` | 模型 id，必须与文件名一致（`qwen-max.json` → `"qwen-max"`） |
| `displayName` / `vendor` / `family` | 人话名字、厂商、同底座家族（家族用于继承） |
| `status` | `未测` / `部分实测` / `已实测`，三档，见下 |
| `supportsTools` | `openai` / `anthropic` / `unknown` |
| `tests` | `calls`（去重调用数）、`errors`、`sessions`、`period` |
| `rules` | 这个模型专属的条目 id 数组，必须已存在于 `catalog/*/rules.json` |

## 三档状态，卡得很死

- **未测**：`tests.calls` 必须为 0，`rules` 必须为空。只能从 `inheritsFrom` 继承别人的条目，且要标「待验证」。
- **部分实测**：`calls > 0`，只能对自己测过的那类问题下结论，`notes` 里写清测了什么、没测什么。
- **已实测**：需覆盖参数形态、文本写入、工具选用、多轮顺序四类，`calls > 0`。

标错档 `tools/validate.js` 会直接报错：`未测的模型不许挂条目`、`标了已实测但 tests.calls 为 0`。
这不是形式主义——一个没测过就挂 block 级条目的模型档案，会让别人误以为那条规矩有依据。

## 你的数字和你有关

命中率取决于你的工具集、你的习惯、你让模型干的活。
同一个模型在两个人手里，参数出错率能差一个数量级。
所以档案里的数字是**参考基线**，不是通用结论；自己的档案要自己跑出来。
