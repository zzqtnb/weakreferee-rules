# 判据库

一条一句，挑你要的那几条。这里只写「检查什么、什么时候会撞上、撞上了怎么办」，**具体的判定写在 `packs/` 里**——库里不放正则，就不会出现两份说法对不上的情况。

共 **32 条**，铺满 7 个域。动作三档：**拦下**（拒了这次调用）、**提醒**（放行但记一笔）、**记账**（只写日志，不打断）。表里的动作是**默认值**，装到你自己机器上想怎么调都行，改法见 `CONTRIBUTING.md`。

## 人群标签

每条都挂着「主要服务谁」。人群**只用来挑包**，不影响判定——同一条规矩，程序员装上和学生装上跑的是同一段代码。挑包见 `packs/`。

| 标签 | 中文 | 典型场景 |
|---|---|---|
| `dev` | 写代码改文件 | 改脚本、改配置、跑测试、提交 |
| `student` | 作业论文报告 | 写论文、查文献、交课程作业 |
| `writer` | 写小说 | 长篇连载、设定一致性、一章一章往前推 |
| `research` | 查资料做调研 | 搜资料、比对来源、写调研稿 |
| `office` | 办公文档表格 | Word、Excel、报表、PPT |
| `ops` | 装环境运维 | 装软件、改服务、清磁盘、连服务器 |
| `chat` | 只聊天问答 | 不碰文件，纯问答与写东西 |
| `general` | 通用 | 谁都可能踩，不分职业 |

## 待评的十条为什么还没进包

现有 22 条都能在**这一次调用**里判完：看参数长什么样、看命令串里有没有危险词、看文件扩展名。新加的十条大多不在这里——**它们的错发生在两次调用之间**：

- 「改完没跑」要等下一次调用才知道跑没跑
- 「没查过却写出 DOI」要回头看这一整轮查过没有
- 「改了表格没重算」要看后面有没有重算这一步
- 「同一个东西动了两遍」要比对前后两次调用

判定引擎在每次工具调用前跑一次，**看不见时间维度**。要么给会话加一份很轻的状态（查没查、跑没跑、动过哪些文件），要么这十条只能停在库里当说明。这是覆盖面变大真正的瓶颈，不是想法不够。

另外三条（重复劳动、过早收工、对外发送留副本）只有工程经验，没有研究级统计；按库里的规矩，**推断最多只能提示，不能拦**。

## 怎么用

- 只看不装：读这一页，挑编号，再打开对应 json 看细节
- 按人群挑：表里的人群列就是入口。人群包还没做——等判定引擎能看见「跨调用」的状态之后再组，否则挑出来的大半是判不了的条目
- 要真拦：装 `dsh-judge-gate`（见仓库根 README），或把这些条目写进你自己的判据包
- 想加一条：走 `CONTRIBUTING.md` 的四道关；判据库这边由作者手工合并，不接受直接提 PR 改条目
