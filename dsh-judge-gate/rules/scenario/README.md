# 场景判据包（scenario）：这套东西是预置防护，装之前请先自己测

## 这 11 条从哪来

不是从作者的操作日志里统计出来的。作者本机（一台 Windows 工作机，主要干文档、脚本、网页取数）**没有**数据库迁移、云 CLI、批量删盘这类操作，所以这 11 条的真实命中数是 **0**——回放 35,651 次历史调用，一条都没有触发过。

它们的来源是**三起公开事故反推**：

| 事故 | 反推出的判据 |
|---|---|
| GitLab 2017-01-31 在 primary 上误跑 `rm -rf` 删掉数据库目录 | `DELETE-ROOT-01`、`DELETE-UNIX-RF-01` |
| AWS 用户拼错桶名 + `aws s3 rm --recursive` 清掉 4,000 张照片 | `CLOUD-STORAGE-PURGE-01`、`CLOUD-PROD-NAME-01` |
| diskpart 误清分区、丢 2 TB 素材 | `DISK-FORMAT-01` |

另几条（`DB-MIGRATE-01`、`DB-PROD-CONN-01`、`DB-SQL-FILE-01`、`CLOUD-TERMINATE-01`、`CLOUD-IAM-DELETE-01`、`DELETE-FOREIGN-DRIVE-01`）是从「生产库/生产资源被误改」这一类故障模式补的。

## 所以：这些判据的正确性**没有真实数据支撑，只有构造样本**

每条判据的 `selfTest` 是作者自己写的构造样本（11 条共 55 例，全部能过）。构造样本只能证明「这条判据按设计的形态能响」，不能证明：

- 它在你环境里的写法都能覆盖
- 它不会误拦你的正常操作

**判断标准仅供参考**，作者只能保证「按设计意图它应该这样判」。你的环境里可能天天跑的东西，作者一辈子没跑过。

## 装之前请做这三件

1. **先跑 selfTest**：`node weakreferee-cli.js selftest`，看这 11 条是不是全绿。不绿说明你的引擎版本与这个包不匹配，先别装。
2. **先降成提示档观察一周**：把 `action` 从 `block` 改成 `warn`，让它只记不拦。一周后翻日志，看命中的那些到底该不该拦；确认没有误拦再改回 `block`。改法与改哪个字段见每条判据的 `fix` 字段。
3. **把你自己的写法补进样本**：`limits` 字段里写清楚了这条不管什么；把你环境中被误拦的形态写进去，下次就不会错。

## 每条判据自带的三样东西

- `scene`：为什么需要这条（人话，带事故来源）
- `limits`：这条**不管**什么，以及已知会误拦的情况
- `fix`：误拦了怎么处置（改 action、加豁免、还是整条下架）
- `advisory`：这条有没有真实数据支撑（多数写着「作者本机无此场景，仅供参考」）

## 一句话

这包东西是**给别人的环境补的防线，不是作者验证过的结论**。装上就拦、拦错了还不知道为什么，那比不装更糟——所以默认建议是先 `warn` 观察，别一上来就 `block`。
